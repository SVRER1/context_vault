# Context Vault software guide

This document describes the software currently present in this directory. It is organized into six domains with equal ownership weight: each domain represents about one sixth of the work needed to understand, maintain, and extend the product. The boundaries are responsibility boundaries; a user action often crosses several of them. File paths below are relative to this directory. `README.md` is the shorter installation and usage guide; this file is the implementation map.

The application is a local file workspace. A **vault** is a user-selected directory. The program keeps its index and operation history in SQLite outside that directory, finds evidence in its files, and previews file changes before applying them. Python 3.11+, SQLite with FTS5, and the dependencies in `pyproject.toml` are required. The CLI uses Typer and Rich; the active desktop UI uses PySide6. Ollama is optional for synthesized answers and generated prose. The six domains below divide both explanation and future maintenance effort approximately equally; each has its own responsibilities, files, data contract, and verification focus.

## Domain 1 of 6 — Application entry points and user interfaces

**Responsibility and approach.** This domain turns user actions into service calls and presents results. `run.py` chooses the desktop application when invoked without arguments or with `desktop`, and otherwise passes arguments to the CLI. `pyproject.toml` publishes the `cvault` command through `cli.main:app`. `desktop/main.py` constructs the Qt application and `ContextVaultApp`. Both interfaces use `ServiceContainer`, so they share vault selection, indexing, search, planning, and generation behavior instead of maintaining separate implementations.

**CLI path.** `cli/main.py` contains the complete Typer command surface: `open`, `vaults`, `status`, `scan`, `index`, `ask`, `search`, `query`, `duplicates`, `organise`, `move`, `copy`, `route`, `rename`, `apply`, `tag add/remove/list`, `peek`, `chart`, `generate`, `audit`, `undo`, `recover`, `chat`, and `desktop`. It stores the last active vault path in `active_vault.json` under the application data directory, validates an optional subfolder scope, and renders search hits and saved operation plans. `ask` returns retrieved evidence by default; `--synthesize` explicitly requests generated prose. `apply` is the commit step for a previously reviewed plan. CLI input and output formatting live here, while the underlying behavior belongs to later domains.

**Desktop path.** `desktop/app.py` owns the main window, sidebar navigation, active vault context, and initial indexing. `desktop/workers.py` runs long operations in `QThread` workers and uses the container's database lock to serialize jobs sharing a vault SQLite connection. `desktop/pages/welcome_page.py` opens recent or newly selected vaults. `search_page.py` displays results and tag actions; `organise_page.py` previews and applies organization plans; `audit_page.py` shows history, recovery, and undo; `duplicates_page.py` displays exact and likely version groups. `chat_page.py` handles questions, source scope, citations, charts, and recent artifacts; `generate_page.py` requests derived documents and charts; `settings_page.py` manages the optional model settings. `desktop/widgets/rule_builder.py` constructs the same validated rule AST used by the CLI, including nested AND/OR groups and NOT.

**Launch and packaging files.** `launch.bat`, `ContextVault.vbs`, `create_desktop_shortcut.bat`, and `create_desktop_shortcut.ps1` provide Windows launch and shortcut paths. `assets/icon.png` and `assets/icon.ico` are desktop branding assets. `requirements.txt` lists runtime packages and `pyproject.toml` defines project metadata, packaging, dependencies, optional test dependencies, the script entry point, and pytest settings. `sample_grades.csv` is a small example input for chart work. `README.md` describes installation, commands, query examples, and testing. The package markers `cli/__init__.py` and `desktop/__init__.py`, plus `desktop/pages/__init__.py`, make those directories importable.

**Current interface boundary.** `desktop/web/index.html`, `desktop/web/styles.css`, and `desktop/web/app.js` are older web interface assets retained in the directory. The current `desktop/main.py` starts PySide6 and does not load those files. They should not be treated as the active UI contract. A future web UI would need an explicit entry point and compatibility work with the current services.

**How to verify this domain.** `python run.py --help` or `cvault --help` checks CLI registration. `python -m desktop.main` starts the desktop UI when PySide6 is installed; set `QT_QPA_PLATFORM=offscreen` for headless GUI tests. Relevant tests are `tests/integration/test_cli_workflows.py`, `tests/integration/test_interface_parity.py`, `tests/unit/test_desktop.py`, and `tests/unit/test_desktop_rules.py`. The interface parity tests matter because the GUI builder and CLI parser must lead to the same selection and preview behavior.

## Domain 2 of 6 — Vault identity, configuration, data contracts, and persistence

**Responsibility and approach.** A vault root is the hard boundary for source files and destination paths. `contextvault/core/vault.py` wraps the selected root and supplies `validate_path`, relative and absolute path conversion, and optional subfolder scope checks. `contextvault/core/paths.py` resolves paths and rejects escapes. `contextvault/retrieval/filesystem_policy.py` provides the shared ignored-source and scope policy, excluding application internals, hidden implementation folders, and generated output from source discovery. Every service that accepts a scope must validate it against this boundary before reading or changing files.

**Configuration and common types.** `contextvault/core/config.py` defines `AppConfig`, defaults, the application data location, `config.json` loading and saving, retrieval budgets, chunk sizes, generated-output folder, and Ollama endpoint/model settings. On Windows the default data root is `%LOCALAPPDATA%\ContextVault`; vault-specific data is beneath its `vaults` directory. `contextvault/core/models.py` defines shared records such as `VaultInfo`, `FileRecord`, `ChunkRecord`, parsed sections, operation records, generated assets, citations, and answer/search results. `contextvault/core/exceptions.py` names domain failures; `contextvault/core/events.py` supplies the event bus used by scanning. `contextvault/core/__init__.py` is the package marker.

**Storage layout.** `contextvault/storage/database.py` opens SQLite with WAL and foreign keys, offers query and transaction helpers, and initializes the schema. `contextvault/storage/schema.py` defines the legacy tables and newer tables for files, chunks, FTS, tags, index runs, saved plans, and per-item operation journals. `contextvault/storage/migrations.py` applies versioned upgrades using `PRAGMA user_version` (currently version 5), checks FTS5, and backs up an unversioned database before migration. `contextvault/storage/registry.py` registers and reopens vaults in the application database. `contextvault/storage/index_repository.py` centralizes file/chunk upserts, extraction state, tags, and index-run records. `contextvault/storage/__init__.py` is the package marker. The application database stores the vault registry; each opened vault also has its own database under its data directory. Indexed paths are vault-relative so the current vault root remains the source for absolute paths.

**Lifecycle and service ownership.** `contextvault/services/service_container.py` constructs global and vault-scoped services lazily. Opening a vault establishes its identity, database, and active service set; closing it clears vault-scoped state. Its `database_lock` protects desktop worker use of a shared connection. `contextvault/services/vault_service.py` registers/opens vaults, triggers scans and indexing, and reports status. `contextvault/services/tag_service.py` resolves a file by ID or relative path and updates metadata tags without changing file bytes. `contextvault/services/__init__.py` is the package marker. The provider for model output is also lazy, but its behavior is described in Domain 6.

**Data and safety contracts.** The index stores normalized relative path and key, timestamps, size, SHA-256, MIME family/type, parser and extraction status, document metadata, located chunks, and labels. Source content is separate from generated files and application state. File IDs are kept when a change can be matched unambiguously; identical hashes alone do not prove that two ambiguous files are the same identity. SQLite transactions protect database changes, but they cannot make external filesystem mutations atomic; Domain 5 describes the journal that addresses that gap.

**How to verify this domain.** Check path rejection, scoped access, schema upgrades, and tag behavior with `tests/unit/test_paths.py`, `tests/unit/test_scoped_workspace.py`, `tests/unit/test_storage_migrations.py`, `tests/integration/test_filesystem_isolation.py`, and `tests/integration/test_vault_workflow.py`. Preserve existing data when changing migrations, and make any new schema change idempotent. These tests and a real reopened vault are the key evidence for persistence changes.

## Domain 3 of 6 — File discovery, extraction, and incremental indexing

**Responsibility and approach.** This domain turns eligible vault files into durable metadata and searchable passages. `contextvault/indexing/index_service.py` is the canonical reconciler. It walks the vault, applies the ignored-source policy, compares current files with indexed records, hashes when needed, extracts changed content, replaces affected chunks and FTS rows, and prunes vanished files only when the scan is safe enough to do so. Unchanged size and nanosecond modification time avoid repeat hashing and extraction. Changed metadata with unchanged bytes can refresh records without re-parsing. A unique, supported move may preserve a file ID; ambiguous external moves may receive a new ID.

**Discovery and integrity files.** `contextvault/indexing/scanner.py` is a compatibility wrapper around the reconciler and emits scan events. `contextvault/indexing/fingerprint.py` provides SHA-256 and integrity checks. `contextvault/indexing/watcher.py` supports filesystem change observation, while explicit `scan` and on-demand reconciliation remain the reliable paths. `contextvault/indexing/chunker.py` splits normalized document sections into overlapping, located chunks using the configured token target and overlap. `contextvault/indexing/extraction.py` selects a parser, normalizes text and metadata, enforces metadata bounds, and reports `ok`, `empty`, `unsupported`, `truncated`, or `error`. `contextvault/indexing/__init__.py` is the package marker.

**Format adapters.** `contextvault/parsers/base.py` defines the parser interface and `contextvault/parsers/registry.py` registers the defaults. `plaintext.py` covers ordinary text, Markdown, source, and other text-like formats; `pdf.py` extracts PDF content; `docx.py` handles Word files; `pptx.py` handles slides; `spreadsheet.py` handles CSV and spreadsheets; `image.py` implements the optional OCR route. The parsers package marker is `contextvault/parsers/__init__.py`. Parser output is converted to a `ParsedDocument` with sections and locations where available: page, slide, heading, line, sheet, cell range, and offsets. An unsupported or unreadable file is still represented in metadata. Image text is not promised when OCR is unavailable.

**Index data flow.** `VaultService.index_vault` or a search/rule request reaches `IndexService.reconcile`. The service creates an index run, discovers eligible files, compares them with `files` rows, invokes `DocumentExtractor` only where needed, chunks successful text, and writes `chunks` plus the FTS5 table through `IndexRepository`. It records extraction completeness and errors. Search and rule selection normally reconcile first; an internal cached freshness policy can deliberately use the existing snapshot. The explicit `cvault scan` command reconciles and `cvault index` reports extraction statistics. `Generated/`, hidden/internal directories, and implementation caches are excluded so derived outputs do not become source evidence.

**Why completeness is explicit.** Content rules and answers cannot safely infer that a document lacks a phrase when no reliable text was extracted. The `extract_status` value and run diagnostics therefore flow into Domain 4 as an **unknown** result. This is especially important for encrypted, unreadable, unsupported, truncated, or image-only files. Similarly, a failed scan avoids confident deletion of records that might merely have been unavailable during discovery.

**How to verify this domain.** `tests/unit/test_incremental_index.py`, `test_extraction.py`, `test_chunking.py`, `test_parsers.py`, and `test_hashing.py` cover the main transformations. `tests/integration/test_deterministic_vault_workflow.py` and `test_vault_workflow.py` exercise indexing through the public workflow. For an extractor change, check both the text and its location metadata, and check that failures become incomplete rather than false negative matches.

## Domain 4 of 6 — Query language, ranked search, and evidence retrieval

**Responsibility and approach.** This domain converts a question or typed rule into bounded, explainable file selections. `contextvault/query/parser.py` tokenizes and parses text queries; `ast.py` defines immutable `All`, `Any`, `Not`, and `Predicate` nodes and their serialization. `validation.py` canonicalizes fields and operators, parses sizes and ISO dates, and restricts regex to bounded name/path patterns. `errors.py` provides actionable parse and validation errors. `results.py` holds the three-way selection result. `planner.py` uses parameterized SQLite predicates and FTS5 for content. `executor.py` evaluates a validated AST over one in-scope indexed universe. `contextvault/query/__init__.py` is the package marker.

**Rule behavior.** Rules can address `name`, `path`, `extension` (also `type`), `mime`, `content`, `tag`, `hash`, `size`, `modified`, and `created`. Boolean groups and parentheses are supported. Content can match terms or an exact phrase; comparisons are typed; regex is limited to filename/path and has validation and a candidate cap. The executor distinguishes **matched**, **excluded**, and **unknown** IDs. `NOT` preserves unknowns instead of treating missing extraction as proof of absence. AND/OR combine those three states, which keeps routing and search from acting on uncertain content.

**Ranked indexed search.** `contextvault/retrieval/search_models.py` defines `SearchRequest`, passage/file hits, and diagnostics. `search_service.py` reconciles by default, optionally intersects a rule selection, queries FTS5, ranks passages with BM25, and adds deterministic filename/heading boosts. It returns excerpts, source locations, file paths, extraction completeness, unknown IDs, and a run ID. Ties use normalized path and stable file ID. A whole quoted free-text query is treated as a phrase; ordinary words are tokenized for a broader search. Limits bound returned files, passages per file, regex candidates, and ranking rows. This path has no model ranking, embeddings, or vector database.

**Live filesystem evidence path.** A separate bounded path supports evidence-backed answers and generation. `contextvault/retrieval/filesystem_models.py` defines requests, surveys, candidates, passages, and evidence documents. `filesystem_policy.py` validates scope; `filesystem_survey.py` enumerates it; `candidate_discovery.py` scores possible files; `agent_selection.py` selects a bounded subset; `selective_reader.py` reads only those files; `evidence.py` creates the evidence document. `filesystem_service.py` orchestrates the rounds and limits. `citations.py` formats source references, and `lexical.py` supplies lexical chunk search helpers. `contextvault/retrieval/__init__.py` marks the package. This path is also deterministic; the former agent terminology in some filenames does not give a model authority over file selection.

**User-visible flow.** `cvault query` or the GUI rule builder reaches the AST and `RuleExecutor`; `cvault search` reaches `SearchService`. `contextvault/services/rag_service.py` uses ranked indexed hits for ordinary `ask` when a search service is present, and uses bounded live filesystem evidence for explicit synthesis. Returned citations refer to file and location information already retrieved. Generated prose is handled only after evidence selection in Domain 6.

**How to verify this domain.** `tests/unit/test_query_parser.py`, `test_rule_executor.py`, `test_search_service.py`, `test_filesystem_retrieval.py`, `test_subfolder_rag.py`, and `test_evidence_generation.py` cover parsing, scope, ranking, unknowns, and evidence. `tests/integration/test_query_retrieval.py` checks the public flow. When changing a predicate, validate both CLI text parsing and the GUI AST path, including incomplete extraction and NOT behavior.

## Domain 5 of 6 — Organization plans, file execution, recovery, and duplicates

**Responsibility and approach.** File mutation is a two-stage operation: create a persisted preview, then explicitly commit that exact plan. `contextvault/filesystem/plan_models.py` defines routes, fingerprints, plan issues, and `FileOperationPlan`. `plan_service.py` validates scope, selects files with the Domain 4 rule executor, applies first-match routing or deterministic grouping, computes exact destinations, and persists immutable previews with a digest and expiry. It reports conflicts, skipped files, warnings, and estimated work before any source file changes. `move`, `copy`, `rename`, `route`, and `organise` use this plan contract. A model-classified or custom destination is not accepted by the active deterministic plan path; callers must provide an explicit rule or supported grouping.

**Commit path.** `contextvault/filesystem/execution_service.py` accepts a plan ID, matching digest, and explicit approval. It rechecks plan status, vault, source size/mtime/hash, scope, destinations, collisions, and free space. It records a batch and each item before mutating files. A destination is staged as a temporary verified copy, published without overwriting an existing path, and only then is a move source removed after another hash check. The index and journal are updated per item. Case-only renames have a dedicated path. A batch may finish partially, because SQLite cannot atomically include filesystem operations. A failure is recorded as `needs_recovery` rather than presented as a clean all-or-nothing rollback.

**Recovery, audit, undo.** `contextvault/filesystem/recovery.py` inspects paths, temporary files, recorded states, and hashes before recommending or performing a safe retry/finalize action. `undo.py` checks current path/hash preconditions and refuses unsafe reversal; a copy is not described as a reversible move. `contextvault/services/audit_service.py` exposes history, batch inspection, recovery, and undo to both interfaces. `filesystem/operations.py`, `permissions.py`, `transactions.py`, and `verification.py` hold lower-level or compatibility helpers for file actions, permission checks, transactions, and verification. `contextvault/filesystem/__init__.py` is the package marker. Always trace a new mutation through the persisted plan and journal rather than calling a low-level helper directly from a UI.

**Organization and duplicate modules.** `contextvault/services/organisation_service.py` adapts the UI and CLI to plan creation/commit and duplicate detection. `contextvault/organisation/deterministic.py`, `rules.py`, and `planner.py` encode traditional grouping strategies. `executor.py` is an older direct `FileOperations` executor for `OrganisationPlan`; it does not implement the current persisted plan and per-item journal contract, so new public mutation flows should use `ExecutionService`. `semantic.py` and `hybrid.py` remain in the tree as older strategy helpers, but the active plan service rejects model-selected destinations. `contextvault/organisation/__init__.py` is the package marker. `contextvault/duplicates/exact.py` groups equal SHA-256 files; `versions.py` flags likely versions using filename similarity and version suffixes; `models.py` defines the result group. `contextvault/duplicates/__init__.py` marks that package. Detection reports candidates; it does not automatically delete them.

**How to verify this domain.** `tests/unit/test_operation_plans.py`, `test_journaled_operations.py`, `test_recovery_undo.py`, `test_filesystem.py`, `test_organisation.py`, `test_custom_organisation.py`, and `test_duplicates.py` exercise previews, collisions, partial failure, and identity. `tests/integration/test_operation_recovery.py` and `test_deterministic_vault_workflow.py` cover public flows. The key safety check is that preview leaves files unchanged, commit refuses stale or colliding state, and undo refuses when current bytes no longer match the journal.

## Domain 6 of 6 — Agent routing, optional generation, tools, and project verification

**Responsibility and approach.** Natural-language convenience and derived outputs sit above the deterministic core. `contextvault/agent/intent.py` classifies a user request, `orchestrator.py` dispatches it to search, question answering, duplicate detection, organization preview, generation, charting, peeking, status, or capability descriptions, and `result.py` defines the returned result. `contextvault/agent/__init__.py` is the package marker. The orchestrator can translate a conversational request into an existing service call, but the underlying source selection and filesystem destinations are bounded by the other domains. Its chat and UI adapters should display a plan for review rather than silently committing a move.

**Optional model boundary.** `contextvault/llm/client.py` defines the provider interface, `ollama_client.py` speaks to a locally configured Ollama endpoint, `prompts.py` contains prompt templates, and `schemas.py` defines structured model responses. `contextvault/llm/__init__.py` is the package marker. `contextvault/generation/artifact_provider.py` wraps model access lazily: it constructs/checks the client only for explicit synthesis or generated content, and receives already selected evidence. Indexing, rule matching, ranked search, tag maintenance, operation planning, commit, audit, and recovery have no model dependency. `contextvault/services/rag_service.py` distinguishes deterministic `ask` from explicit `synthesize`; a missing provider affects the latter.

**Derived files.** `contextvault/services/generation_service.py` calls `contextvault/generation/generator.py` for summaries, study guides, revision notes, flashcards, quizzes, timelines, and reports. The generator retrieves bounded, scoped evidence, chooses a template from `templates.py` and `llm/prompts.py`, and asks the artifact provider for prose when available. If evidence is insufficient or the provider is unavailable, it writes a deterministic evidence or insufficiency report instead of pretending that a model answer succeeded. `writers.py` publishes Markdown under the vault's `Generated/` directory with a safe single-file name and collision suffix; `pdf_compiler.py` supports PDF compilation. Generated asset metadata is recorded in SQLite when possible. `contextvault/generation/__init__.py` is the package marker. Generated output is excluded from indexing as source material.

**Local tools.** `contextvault/tools/base.py` defines tool metadata, registry, and results. `peeker.py` provides shallow, bounded file/directory inspection; `charts.py` reads tabular data and produces PNG charts. `contextvault/tools/__init__.py` is the package marker. These tools can be reached from CLI or the desktop chat/generate surfaces, but must still respect a vault scope and output path. `sample_grades.csv` is an example dataset, and the chart dependency is Matplotlib. A user can use the deterministic core without Ollama; generated prose quality depends on the available provider and evidence.

**Development and verification.** `tests/unit/test_orchestrator.py`, `test_ollama.py`, `test_offline_core.py`, `test_pdf_compiler.py`, `test_charts.py`, `test_peeker.py`, and `test_tools.py` cover dispatch, provider absence, and local tools. `tests/integration/test_vault_workflow.py` exercises the cross-domain route; `tests/__init__.py`, `tests/unit/__init__.py`, and `tests/integration/__init__.py` mark test packages. Install with `pip install -e .` and optional test dependencies with `pip install -e .[dev]`; then run `python -m pytest -q` with `QT_QPA_PLATFORM=offscreen` for headless Qt. At the time this guide was written, the suite ran in this directory with 135 passed and 2 skipped using Python 3.11 and the installed dependency set. Hardware, permissions, locks, FTS5 availability, and filesystem boundaries can produce different runtime outcomes; fault-injection tests cover representative recovery states rather than every physical failure.
